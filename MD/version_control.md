# version_control.md — how changes are numbered, recorded and pushed

Same scheme as Surya's other projects (Dukaan Dost, TARANG): **builds** and **InBuls**, pinned by git tags. Read this before committing.

## 1. Two kinds of change

| Kind | What it is | Label | Number |
|---|---|---|---|
| **Build** | Something the **reviewer sees in the app**: a screen, a flow, how an error shows, the APK | `build-N` | 1000, 1001, … |
| **InBul** (internal build) | Everything else: `MD/` docs, research, scripts, tests, snapshots, tooling | `InBulNN` | 01, 02, … |

The **git tag is the source of truth** for the number. A commit title never carries "(Build N)". Tags are lightweight and are never moved or renumbered. Builds are **batched** — about ten fixes to a build — so the list stays meaningful.

```
change made
   ├─ a user would notice it ──> Build N ──> commit + MD/builds/build-N.md + CHANGELOG.md entry + tag build-N
   └─ internal               ──> InBulNN ──> commit titled "InBulNN: ..." + tag InBulNN (no report, no changelog entry)
```

## 2. Build or InBul?

| Change | Label |
|---|---|
| A screen, a widget, copy, a colour, the API client, the APK | **Build** |
| `MD/*.md`, `snapshots/`, `test/`, `scripts/`, README | **InBul** |
| A fix nobody would see (a test, a lint) | **InBul** |
| A fix the reviewer would see | **Build**, batched with the next ones |

When in doubt: would Surya mention it to the reviewer? Build. If not: InBul.

## 3. Files involved

| File | What | Who writes it |
|---|---|---|
| `MD/builds/build-N.md` | One report per build: what, why, how checked, next; plus the staged file list | Hand-written part once; file list rebuilt by the script |
| `CHANGELOG.md` | Build history, newest first | **Generated** by `scripts/changelog.mjs`. Never by hand |
| `scripts/changelog.mjs` | The tool (Node ≥ 18, no dependencies) | Code |
| `MD/decisions.md`, `MD/tasks.md`, `MD/tried_*.md` | Why, what's next, what worked | By hand |

## 4. Making a build

```
git add <files of the change>                       # the report reads the staged diff
node scripts/changelog.mjs --pending "<title>" "<what changed, one or two sentences>" \
    --why "<why>" --verified "<how it was checked, honestly>" --next "<next improvement>"
git add MD/builds CHANGELOG.md
git commit -m "<same title>" -m "<body: what, why, verified>"
node scripts/changelog.mjs --tag                    # pins build-N on HEAD; checks the title matches
```

Title style: plain words, what the product now does. No prefixes, no number.

## 5. Making an InBul

```
node scripts/changelog.mjs --next-internal          # prints e.g. InBul03
git add <files>
git commit -m "InBul03: <short description>" -m "<short body>"
node scripts/changelog.mjs --tag                    # pins InBul03
```

A build and an InBul in one sitting are two commits.

## 6. Pushing

- **Commit and push only when Surya asks.**
- Push branch and tags together: `git push origin main --tags` (tags are lightweight, so `--follow-tags` would skip them).
- Remote: `https://github.com/xeyynon/CS-Infotech-.git`, branch `main`, no force pushes.
- Commits carry only Surya's name. No co-author trailers, no "generated by" lines.
- Look something up later: `git show build-1000`, `git diff build-1000 build-1001`, `git log --oneline --decorate`.

## 7. Checks before every commit

```
cd calley_app
flutter analyze                    # 0 issues
flutter test                       # all green; regenerates nothing
flutter test test/snapshots --update-goldens   # only when the UI changed on purpose; then commit snapshots/
```
Never commit: keystores, `key.properties`, `.env`, anything from `.playwright-mcp/`.

## 8. Quick card

```
build:   git add <files> -> changelog.mjs --pending "title" "summary" --why .. --verified .. --next ..
         -> git add MD/builds CHANGELOG.md -> git commit (same title) -> changelog.mjs --tag
inbul:   changelog.mjs --next-internal -> git add -> git commit "InBulNN: title" -> changelog.mjs --tag
push:    git push origin main --tags        (only when Surya says so)
never:   "(Build N)" in a title · hand-editing CHANGELOG.md · moving a tag · keys
```
